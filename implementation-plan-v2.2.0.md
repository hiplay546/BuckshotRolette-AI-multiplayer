# План реализации для Buckshot Roulette v2.2.0

## Выбранный путь

Разрабатывается отдельный адаптер для установленной Steam-версии `v2.2.0`. Старый BRML не используется: его патч предназначен для `v2.1.0.11`. BRMLNeo можно изучать как исходный код Godot-загрузчика, но не считать готовой установкой.

Первый результат — мод в отдельной рабочей копии, который только пишет JSONL-события реальной игры. Он не вызывает API моделей и не управляет игроками.

## Этап 1. Изолированная рабочая копия

1. Создать каталог `C:\Users\Daniil\Desktop\modbucksot\work\game-v2.2.0`.
2. Скопировать в него исходные файлы игры и записать SHA-256 исходного EXE в манифест.
3. Запускать эксперименты только из этой папки.
4. Хранить логи и извлечённые ресурсы вне исходной Steam-установки.

Потребуется около 1.3 ГБ свободного места для копии и ещё место для распакованных Godot-ресурсов.

## Этап 2. Анализ Godot-ресурсов

1. Взять GDRE Tools из официального репозитория GDRETools.
2. Распаковать содержимое копии игры в `work\extracted`.
3. Зафиксировать версию Godot и список сцен, скриптов, автозагрузок и классов.
4. Найти фактические обработчики: смены хода, предметов, взятия ружья, прицеливания, выстрела, здоровья, выбывания, зарядки и сетевых событий.
5. Сопоставить эти точки с ручной игрой. Названия классов и методов до распаковки не придумывать.

## Этап 3. Минимальный мод-адаптер

Создать модуль `telemetry_adapter` с одной ответственностью: после фактического игрового события добавлять запись в `logs\events.jsonl`.

Каждая запись содержит:

```json
{
  "event_id": 1,
  "timestamp_utc": "2026-11-02T00:00:00Z",
  "match_id": "manual-test-001",
  "type": "turn_changed",
  "phase": "items",
  "visibility": "public",
  "data": {}
}
```

Первая версия фиксирует только подтверждённые игрой события:

- начало и завершение матча или раунда;
- активного игрока;
- выдачу и использование предмета;
- личный и публичный результат предмета;
- взятие ружья и выбранную цель;
- выстрел и его результат;
- здоровье, статус, смену хода и выбывание.

Если конкретное событие нельзя прочитать достоверно, адаптер пишет техническое предупреждение. Он не выводит предполагаемые значения.

## Этап 4. Ручная проверка

Провести тест в реальном режиме, который поддерживает установленная игра, и сопоставить журнал с происходящим на экране. Отдельно проверить:

- повторный вызов не дублирует событие;
- приватный результат не попадает в публичную запись;
- выбывший игрок больше не отмечается как активный;
- порядок событий соответствует игре.

Если режим на четыре места доступен, это тестируется отдельно. Одиночная игра подтверждает только телеметрию одиночного режима.

## Только после телеметрии

1. Добавить безопасный исполнитель одной ручной команды для одного игрока.
2. Добавить локальный организатор фаз и идемпотентность команд.
3. Подключить одного API-агента с ограничениями расходов.
4. Подключить четыре независимых контекста и два круга переговоров.

## Что требуется от пользователя при ручном запуске

При первой проверке модифицированной копии нужно сообщить:

- виден ли в главном меню multiplayer;
- сколько игроков допускает закрытая комната;
- есть ли таймер хода и можно ли поставить матч на паузу;
- где игра сохраняет сетевые настройки и журналы.
